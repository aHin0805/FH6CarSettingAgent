## 简介
本文件为 POST /api/chat 聊天接口的完整技术文档，涵盖接口的 HTTP 方法与 URL、请求与响应格式、messages 数组参数结构、流式 SSE 响应机制、sessionId 参数作用、AI 提供商配置对接口行为的影响、任务类型参数（taskType）的动态路由机制、典型汽车调优咨询场景的请求/响应示例、错误处理机制（400、401、500），以及 maxSteps 参数与工具调用机制。

**更新** 本版本新增了任务类型参数支持，实现了轻量（light）和深度（deep）模型的动态路由，为不同复杂度的调优需求提供合适的AI模型选择。

## 详细组件分析

### 接口定义
- HTTP 方法：POST
- URL 模式：/api/chat
- 请求体字段：
  - messages: 数组，元素为对象，包含 role 与 content 字段
  - taskType: 字符串，任务类型，取值为 "light" 或 "deep"
  - sessionId: 可选字符串，用于标识会话上下文
  - vehicleId: 可选字符串，用于关联车辆信息（类型定义存在，但路由未使用）
- 响应：
  - 成功：SSE 流式响应，Content-Type: text/event-stream
  - 失败：JSON 响应，包含 code、data、message

**更新** 新增了 taskType 参数，支持轻量（light）和深度（deep）两种任务类型的动态路由。

### 流式 SSE 响应机制
- 响应头设置：
  - Content-Type: text/event-stream
  - Cache-Control: no-cache
  - Connection: keep-alive
  - X-Accel-Buffering: no（Nginx 缓冲绕过）
- 数据流格式：
  - 以事件流形式推送，每个片段为二进制字节流
  - 若发生错误且响应头尚未发送，返回 JSON 错误
  - 若响应头已发送，则以 SSE 事件形式发送 error 事件
- 客户端处理：
  - Next.js客户端通过ReadableStream API处理SSE流
  - 实时更新聊天界面，提供流畅的用户体验

**更新** 客户端使用现代浏览器的流式API处理SSE响应，提供更好的性能和用户体验。

## 性能考虑
- 流式传输：使用 SSE 逐步推送，降低首字节延迟
- 缓冲控制：设置 no-cache 与 X-Accel-Buffering=no，避免代理层缓存导致的延迟
- 步数限制：maxSteps 控制工具调用与推理深度，防止长对话造成资源占用
- 模型选择：taskType 参数实现轻量和深度模型的智能路由，平衡性能和准确性
- 配置优化：合理设置 AI_BASE_URL 与 AI_MODEL，选择就近节点与合适模型
- 客户端优化：Next.js App Router提供代码分割和智能缓存，提升页面加载性能

**更新** 新增的任务类型参数优化了模型选择策略，提高了系统的整体性能表现。

## 故障排除指南
- 400 错误（messages 为空）：
  - 检查请求体是否包含 messages 字段，且为非空数组
- 401 错误（API Key 未配置）：
  - 确认环境变量 AI_API_KEY 已正确设置
- 500 错误（AI 调用失败）：
  - 查看服务端日志中的错误堆栈
  - 若已开始 SSE 流，检查客户端是否收到 error 事件
- 任务类型相关问题：
  - 确认 taskType 参数值为 "light" 或 "deep"
  - 检查后端是否正确识别任务类型并选择相应模型
- 客户端问题：
  - 检查Next.js版本兼容性
  - 验证SSE连接是否正常建立
  - 查看浏览器开发者工具中的网络请求

**更新** 新增了任务类型相关的故障排除指导。
